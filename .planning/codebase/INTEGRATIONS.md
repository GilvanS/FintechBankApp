# External Integrations

**Analysis Date:** 2026-07-19

## APIs & External Services

**Internal API surface:**
- Custom REST API served from `API/index.cjs`, mounted at both `/api` and `/api/v1` (`app.use('/api', apiRouter); app.use('/api/v1', apiRouter);`)
- Swagger/OpenAPI docs auto-generated by `API/swagger-generate.js` into `API/swagger.json` / `API/swagger.yaml`, served at `/api-docs` via `swagger-ui-express`
- No third-party payment/SMS/email provider SDKs detected (no Stripe, Twilio, SendGrid, etc. in `API/package.json`) — this app appears to simulate fintech operations (Pix, cards, billing) internally rather than integrating real payment rails

**WEB and MOBILE → API:**
- WEB calls the API via native `fetch` in `WEB/services/api.ts` (constant `API_BASE`)
- MOBILE calls the API via Axios (`axios` dependency) plus its own `MOBILE/src/services/api.ts`
- Both frontends ship a `mockApi.ts` (`WEB/services/mockApi.ts`, `MOBILE/src/services/mockApi.ts`) used for demo/offline builds (e.g. GitHub Pages demo) when no live backend is available

## Data Storage

**Databases:**
- PostgreSQL - primary/default local dev target
  - Client: `pg` 8.16 via `API/services/database/PostgresProvider.js`
  - Migrations: Knex (`API/knexfile.js`, `API/migrations/001_initial_schema.js`, `002_invoice_lifecycle.js`)
  - Connection: `POSTGRES_CONNECTION_STRING` env var, or discrete `DB_HOST`/`DB_PORT`/`DB_USER`/`DB_PASS`/`DB_NAME`/`DB_SCHEMA` vars
  - Raw SQL schema files also present: `API/schema.sql`, `API/schema_pg.sql`, `API/schema_pg_fintech.sql`, `API/schema_invoice_lifecycle.sql`
- Databricks SQL - alternate/production provider
  - Client: `@databricks/sql` 1.12 via `API/services/database/DatabricksProvider.js`
  - Selected when `DB_PROVIDER` or `DB_DIALECT` env var equals `databricks` (also the hardcoded default in `DatabaseFactory.js` line 7 and `index.cjs:2742`)
  - Schema mirror: `API/databricks_schema.sql` (also duplicated in `WEB/databricks_schema.sql`, `MOBILE/databricks_schema.sql` for reference)
- Provider abstraction: `API/services/database/DatabaseFactory.js` picks provider at runtime; `DatabaseInterface.js` defines the common contract both providers implement
- `mysql2` is a listed dependency in `API/package.json` but no active MySQL provider file was found — likely legacy/unused

**File Storage:**

## Authentication & Identity

**Auth Provider:**
- Custom - no external identity provider (no Auth0/Firebase Auth/Cognito)
- Implementation: JWT-based, issued in `API/index.cjs` login handler (`jwt.sign({ cpf, role, email }, JWT_SECRET, { expiresIn: '8h' })`, line ~777)
- Token delivered as an httpOnly cookie (`token`), `secure` flag tied to `NODE_ENV === 'production'`, `sameSite: 'lax'`
- Password hashing via `bcryptjs`
- Auth middleware: `API/middlewares/auth.js` exports `bearerAuth`, `requireScope`, `pinGuard`, `withReqId`, `auditLog` — `bearerAuth` throws at startup if `JWT_SECRET` is unset
- MOBILE also integrates native biometric auth via `@aparajita/capacitor-biometric-auth` as a local device-level second factor (not a remote identity provider)
- Login identity field is CPF (Brazilian tax ID), consistent with project memory noting test login `CPF 11111111111`
